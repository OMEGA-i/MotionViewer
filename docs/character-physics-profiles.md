# 角色物理配置与复查

这一轮检查的角色是宵宫、芙宁娜、妮露、彦卿、流萤·春日手信、青衣和无外套飞霄。
原生动作、角色 PMX 和贴图保持原文件；角色配置只调整展示时的服装物理。
身体姿态美化、脚部 IK、手臂避让和手指握持覆盖都不随物理配置自动开启。

## 配置入口

`scripts/render_mmd_compare.py --physics-profile <JSON> --bullet` 读取配置。
配置严格匹配 `asset_sha256` 和导入比例 `0.08`，不匹配即报错。
只覆盖 `bullet` 中明确写出的参数，其余参数沿用命令行与默认值；最终完整设置和
配置指纹写入 `info.json` 的 `physics`。SMPL-X 批量入口也支持此参数，其内容进入
视频缓存签名，避免换了服装设置仍复用旧视频。

```bash
blender --background --python scripts/render_mmd_compare.py -- \
  --asset assets/fbx/pmx/yoimiya/宵宫.pmx \
  --soma '/path/to/004162.soma.npz' \
  --output outputs/my-review/yoimiya-walk \
  --faithful --root-motion source --expression none \
  --foot-contact off --upper-smooth 0 --arm-clearance-degrees 0 \
  --bullet --physics-profile configs/characters/yoimiya_mesh_cloth.json \
  --toon --views three_quarter,side --panels character
```

`visual_verified` 记录已检查的源动作哈希、完整帧段、帧率、视角、展示设置与证据。
它只说明这些样本的检查范围，不能解释为所有动作都自然、所有接触都正确。
新增复查记录会改变配置指纹；历史渲染保留当时实际读取的配置报告，不事后伪造来源。

## 三种实际处理方式

| 角色 | 配置 | 处理范围 |
| --- | --- | --- |
| 宵宫 | `yoimiya_mesh_cloth.json` | 网格 Cloth 解算裙与长衣摆，保留其他头发/饰品 Bullet 物理 |
| 芙宁娜 | `furina_garment.json` | 仅长后摆 HB1 内部关节柔顺，不改腰部锚点 |
| 妮露 | `nilou_garment.json` | 仅长飘带 D/QD 内部关节弯曲，不改原始身体动作 |
| 彦卿、流萤、青衣、飞霄 | 各自的 `*_native_pmx.json` | 保留已复核的 PMX 物理；地面和取景属于另外的展示校准 |

宵宫用服装外表面生成焊接的轻量代理。长衣摆原模型有内外双层，不能把两层近重合
表面一起当作布料自碰撞面。固定区域来自原蒙皮权重；身体碰撞只选择经过检查的
人体/裤子表面，固定接缝面排除碰撞，避免多层外衣和腰部固定约束互相推挤。
原始可见服装和描边通过 Surface Deform 跟随代理，替换部位不再同时受裙骨 Bullet 驱动。

Cloth 解算完成后，把小代理每帧的结果存为形态键，移除其运行时模拟修改器，
使重新打开场景、换机位和数值检查使用固定播放结果。它是物理模拟后的烘焙，
不是重写源动作或给人体加形态键。原可见模型与源文件均未被覆盖。
第一版直接读取内存 Cloth 缓存的实验曾出现重开/再求值差异，因此不能拿那些
未固定缓存的测量当作最终成片的严格几何复现证据。

内部关节规则只能匹配同一条指定骨名前缀的两个动态端点；腰部静态锚点和跨链连接
被保留。规则应用在模型物理构建后、缓存烘焙前，每个修改轴的原值和新值均有报告。

## 接触与自然度的边界

新结果位于 `outputs/characters-2026-10-23/`，正式成片与被否决试验分目录保存。
`native_four_review_manifest.json`、各角色复查清单和 `independent-visual-review.json`
记录实际检查结论。先读这些结论，再使用相应配置。

按全片真实鞋底最低点校准展示地面，只修正地面位置，不会消除不同身体比例造成的
全部滑步或悬空，也没有移动身体或启用脚部 IK。`_review_native_character.py` 把
逐帧鞋底间隙与源数据推断的接触分开记录。

挥剑源动作 `128701` 的四根非拇指手指大多接近伸展；道具挂接本身不能把摊掌变成
自然抓握。本轮不通过覆盖原手指或修改手臂来伪装已经握稳。箱子工作已按用户要求停止。

三角交叉数、单帧中点偏差和较低的峰值都只是诊断。比较必须使用同一表面选择、
动作、完整帧段和机位，仍需观看主视与侧视。局部手腕/裙边交叠、衣片硬感和特定
帧的折落没有因为数值检查通过而自动解决。

宵宫舞蹈的网格布料对照属于有条件的连续性改善：衣摆更柔顺，但腿侧相交增加。
网页保留上版单独视频，不能将新版视为所有质量指标都更好的替代。

## 走路裙摆“撑开”：起步姿势造成，不是走路本身（`--bullet-neutral-settle`，2026-10-23）

用户观察：舞蹈的裙子正常，走路的裙子很怪。侧视图确认：妮露走路前约90帧，前后裙片
**水平撑开像硬纱裙**，流苏横飞；第92–94帧突然塌下，之后才垂下来。舞蹈从第1帧就垂着。

原因在物理的“沉降帧”（第1帧之前的30帧）。沉降期间角色停在**第1帧的姿势**上，
而走路第1帧正处在迈步中间，两条大腿张开44.5°（舞蹈第1帧只有15.6°）。
裙子在一条向前的大腿上沉降，前片就**搭在腿部碰撞体上**被关节链撑住，
一直到减速、两腿并拢（约第90帧）才滑落——这就是之前看到的“92–94帧突然折落”，
不是求解器释放误差。舞蹈第1帧接近站立，所以没有这个问题。

已排除：阻尼（线性、角度都清零，走路时裙摆角度65.5°→65.2°，几乎不变）、
substeps、沉降帧在负帧号（挪到正帧后结果与原来逐位相同，0.0 mm）。

修法：沉降前半段让腿保持模型静止姿势，裙子先自然垂下；后半段用平滑插值把腿
带到第1帧的姿势，让腿从裙子**下面**迈出去。只在第1帧之前（不渲染）给六根腿骨
（大腿、膝、踝）补关键帧；渲染帧的骨盆、手指与原来差 0.0 mm，动作完全不变。

| 妮露走路 | 原来 | 中性沉降 |
| --- | --- | --- |
| 走路时前两排裙片与垂直的夹角 | 65.5° | 41.9°（站立时36.7°） |
| 衣物刚体加速度 p99 / 峰值 | 95 / 415 m/s² | 57 / 164 |
| 第92–94帧塌落 | 有 | 没有 |

对照：妮露舞蹈 42.3°→42.3°，不受影响；芙宁娜走路后摆本来就没被撑住，变化很小。
代价：裙子现在垂在手摆动的位置，走路开头手穿裙的三角相交从11帧/1565对变成12帧/3224对
（三分之四视角下手被裙子挡住，看不出来）。

视频：`converted/walk_skirt_fix_20261023/`（左原、右新，同机位）。
开启：命令行 `--bullet-neutral-settle`，或配置 `"neutral_settle": true`。默认关闭。

## 芙宁娜走路后摆“乱抖”：衣片按条散开（`side_link_rules` + `smooth`，2026-10-23）

中性沉降修好了妮露，但芙宁娜走路的后摆仍然乱抖。放大逐帧看，后摆不是整片在摆，
而是**散成一条条细带，几帧后又合拢**，轮廓一直在变。

原因在后摆（`HB1`）的关节结构：9列×8行的刚体网格，骨骼名 `HB1_<行>_<列>`。
每一列往下的关节几乎是死的（0 mm 滑动、1.4–5.7°），而相邻两列之间的横向连接 `HB1横`
却允许 **35–85 mm 滑动、30°旋转**。于是每列像一根硬棍各自摆，邻列之间被很松的线连着，
整片衣服就会裂成条。妮露的裙子没有这种结构，所以没这个问题。

排除过的：阻尼（两个轴都清零，抖动 2.0→2.4 mm，没变好）、腿的碰撞（离碰撞体100 mm以上的
衣片抖得一样厉害）、关节角度限制（另一位 agent 的配置已经放宽到 ±15°）。

修法两部分，各管一半：

- `side_link_rules`：把 `HB1横` 横向连接的滑动范围缩到原来的 **30%**，让相邻列一起动。
  相邻列间距的变化速度（p95）8.5→3.9 mm/帧。只会收窄、不会放宽，按关节名匹配。
- `bullet.smooth: 1.5`：烘焙后对每个衣物刚体（骨盆坐标系下）做 1.5 帧的高斯平滑，去掉逐帧抽动。
  抖动 9.7→7.6 mm，大于 20 mm 的单帧跳变 449→183，摆幅保留 96%。
  命令行等价于 `--bullet-smooth 1.5`。

配置：`configs/characters/furina_garment_walk_v2.json`（在原来审过的配置上加了这两项和中性沉降；
原配置未改）。舞蹈用同一配置对照过，没有变坏。视频在 `converted/walk_skirt_fix_20261023/`。

## 烘焙后去除整片突跳（`--bullet-despike`，2026-10-23）

注意：妮露走路的“第93帧折落”后来查明是上一节的起步问题，开了中性沉降后它就没有了，
在中性沉降之上再去突跳，峰值只是从164降到75，画面差别很小。去突跳单独对其余片段的作用：

在求解器内部改了三种参数，**全部更差**，不要再试：

| 改动 | 整片突跳帧 | 峰值加速度 |
| --- | --- | --- |
| 原设置 | 9 | 415 m/s² |
| 去掉衣物阻尼 | 10 | 464 |
| substeps 12→30 | 15 | 1306（约束越硬、步长越小，纠正冲量越大） |
| 手指碰撞体 | 27 | 571（手推衣片） |

因此改为 MMD 动画师的做法：**物理照常烘焙，烘焙后清理曲线**。
`core/cloth_despike.py` 把每个动态刚体换到骨盆坐标系（走路本身不算衣物运动），
只把“超过该刚体自身中位加速度6倍且大于20 m/s²”的帧当作突跳，用两端真实速度的
三次 Hermite 曲线（旋转用 slerp）补上；其余帧逐位不变。结果写回刚体关键帧并关闭
Bullet 世界，骨骼约束照常读取，下游不变。必须放在所有烘焙（包括宵宫网格布料）之后。

同机位、同参数重渲结果（`outputs/despike-20261023/`，每个目录有 `compare.mp4`，左原右新）：

| 片段 | 改动的帧×刚体 | 峰值加速度 | 整片突跳帧 |
| --- | --- | --- | --- |
| 妮露走路 | 12.3% | 415 → 121 | 14 → 0 |
| 妮露舞蹈 | 1.0% | 174 → 137 | 1 → 0 |
| 芙宁娜走路 | 4.4% | 297 → 204 | 0 → 0 |
| 芙宁娜舞蹈 | 4.2% | 240 → 56 | 0 → 0 |

各衣物组保留了91–99%的摆动幅度；单刚体的“左裙饰”只保留85%，硬摆部件会被削掉一部分真实摆动。
已经自然的片段几乎不改（舞蹈1%）。默认关闭；配置里写 `"despike": true` 或命令行加 `--bullet-despike`。

## 手穿裙子/大腿：真正原因是身材比例，修法是肩关节外展（`--arm-clearance-degrees 14`，2026-10-23）

用户指出妮露走路手完全埋在裙子里、芙宁娜手压进大腿，判断是手的位置不对。确实如此，
而且原因可以量出来：重定向把源动作的**关节角度**原样搬过来（手臂外展4.5°/8.7°，源动作4.3°/7.6°，
几乎一样），但两个身体比例差很多——源身体两髋关节半宽115 mm，妮露/芙宁娜只有75 mm，
而裙子和大腿外沿并不窄。同样的角度放到这种身材上，手的**位置**就落进了裙子和大腿里。

项目以前有这个修正：pose polish 里的 `arm_abduction_degrees`（默认12°）专门为此设计，
但现在所有渲染都用 `--faithful`，这一项一直是关的。现在单独用 `--arm-clearance-degrees`
打开手臂外展（不带 polish 的其余改动）：只转上臂、保持手的朝向，腿和根骨骼不动；
手臂越抬起转得越少，叉腰、抬手这类动作基本不受影响。上限从4°放宽到20°。

实测（同机位，与已认可的版本对比）：
- 8°：手腕最多外移5.3 cm，手从埋进裙子变成贴着裙面；
- **14°：最多外移9.3 cm，妮露、芙宁娜两只手在走路全程都在裙子/大腿外侧**；
- 舞蹈14°：叉腰仍然叉在腰上（从陷进腰里变成放在腰上），抬手帧不变；手/裙三角相交 20帧→**0帧**。
- 走路14°的三角相交数反而变多（12→137帧），逐帧查过：全是指尖碰到外张裙摆外沿的1–3个顶点、
  在胯下约20 cm处，属于擦边接触，不是手埋进去。这个计数分不清“埋进去”和“擦外沿”，不能单独当结论。

## 手穿裙子：第二轮（2026-10-23），三种做法全部实测

同一套三角相交检测，裙子按材质 `裙` 选取（网格布料会删掉裙子刚体，按刚体选会误报为0）。

**1. 手臂往外移——这条结论之前写错了，已更正，见下一节。** 当时的测试是把手整体水平平移，
在所有高度推同样距离，不等于真实的肩关节外展，得出“不可行”是测试方法的问题。

**2. 刚体手碰撞体**：上一节已测，更差。

**3. 细分网格布料 + 手作碰撞体**（`configs/characters/nilou_mesh_cloth.json`，实验性）：
裙子 `裙` 做成细分一次的布料代理（630→2636面，面宽约27→13 mm，比手指细），
与皮肤 `肌*`、手部材质 `体2` 碰撞。新增 `mesh_cloth.subdivide`（0–2）。

| | 中性沉降 | 网格布料 |
| --- | --- | --- |
| 走路 | 12帧 / 3224对 | 47帧 / 3133对 |
| 舞蹈 | 20帧 / 2298对 | 20帧 / 972对 |

舞蹈穿入量降到约40%；走路相交总量差不多，但分散到更多帧（布料贴着手滑）。
没有一种做法把相交清零。从三分之四镜头看，走路时右手在裙子后面被挡住，
舞蹈第119–132帧是双手叉腰、指尖压进腰线，成片里都不明显。

## 手穿裙子：本轮测过、没有解决

妮露走路第7–17帧右手、舞蹈第119–132帧指尖穿过裙片，深度最多15 mm / 4 mm，
占全部衣物/皮肤三角相交的95–100%。用同一套独立三角相交检测、同一段动作测了四种做法：

| 做法 | 相交帧 | 相交三角对 |
| --- | --- | --- |
| 不改（现成片） | 11 | 1565 |
| 去突跳 | 10 | 1383 |
| 去突跳 + 把衣物顶点推出皮肤 | 8 | 1278 |
| 手指碰撞体 | 8 | 1791 |
| 手指碰撞体 + 去突跳 | 27 | 4512 |

**原因是网格太粗，不是物理不对。** 相交的衣物顶点在手表面法线的**外侧** 13–17 mm、
离手 18–89 mm：裙片一个三角形有好几厘米宽，比整只手还宽，三角形的边从手指中间切过，
三个顶点却都在外面。推顶点去不掉穿过顶点之间的边；碰撞体只推开刚体盒子，
蒙在多根裙骨上的大三角照样切过手指，被推开的衣片还会在后面帧弹回来穿得更多。

要真正解决，需要更细的衣物几何——宵宫用的网格布料代理就是这个思路，
可以按同样方式给妮露的前片做代理。`fit_hand_colliders` 还有一个坑：它按
`cloth_bone_tokens` 选衣物刚体，妮露的裙骨叫 `Q_*`，默认关键字一个都匹配不上。
